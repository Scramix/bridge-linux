# Contributing to Bridge Linux

Thanks for wanting to contribute to Bridge Linux!

Bridge Linux is an open-source project, and contributions are welcome. You do not need to be an expert to contribute. If you have an idea, found a bug, improved some documentation, or want to work on the code, you can help.

## Before contributing

Before making a contribution, please make sure you have read the [Code of Conduct](CODE_OF_CONDUCT.md).

Please also check the existing issues and pull requests before opening a new one. Your issue or idea may already have been discussed.

## Reporting bugs

If you find a bug, please open an issue on GitHub.

Try to include:

* What happened.
* What you expected to happen.
* What you were doing when the problem happened.
* Your Bridge Linux version.
* Your hardware and operating system information when relevant.
* Any error messages you received.

Screenshots and other useful information are welcome when they help explain the problem.

Please do not include passwords, private information, or other sensitive data in an issue.

## Suggesting features

Feature suggestions are welcome.

When suggesting a feature, explain:

* What the feature would do.
* Why you think it would be useful.
* How you think it could work, if you have an idea.

You do not need to have the entire feature planned out before suggesting it.

## Contributing code

Bridge Linux uses several programming languages depending on what part of the project is being worked on.

The main development language for the operating system is **C**. Other languages may be used where they make sense.

When contributing code:

* Keep your code reasonably simple and understandable.
* Follow the existing coding style of the part of the project you are modifying.
* Do not add unnecessary dependencies.
* Do not intentionally add malware, spyware, backdoors, or other harmful code.
* Test your changes before submitting them when possible.
* Explain what your change does in your pull request.

For low-level code, be especially careful. A small mistake in an operating system can cause much bigger problems than a small mistake in a normal application.

## Documentation

Documentation is also a contribution.

You can help by:

* Fixing spelling or grammar mistakes.
* Making confusing explanations clearer.
* Adding missing documentation.
* Fixing broken links.
* Adding examples.
* Improving the Bridge Linux documentation.

You do not need to write code to contribute.

## Pull requests

When submitting a pull request, please explain what you changed and why.

If your pull request fixes an issue, mention the issue number when appropriate.

Please keep pull requests focused when possible. A pull request that changes one thing is usually easier to review than one that changes twenty unrelated things.

Do not worry if your first pull request is not perfect. Changes can be discussed and improved during review.

## Large changes

For large changes, it is a good idea to open an issue or discussion before doing a lot of work.

This gives the project a chance to discuss the idea before someone spends a large amount of time implementing something that may not fit the project.

This is especially useful for major changes to the kernel, installer, desktop, filesystem support, or other core parts of Bridge Linux.

## Keep Bridge Linux's goal in mind

Bridge Linux is designed to make moving from Windows to Linux easier without taking away the power of Linux.

Contributions should generally keep this goal in mind.

Bridge Linux should be approachable for new Linux users while still allowing experienced users to disable or move beyond the Windows-style abstractions when they want to.

## Thank you

Whether you submit a large feature, fix one typo, report a bug, or simply help someone understand how something works, your contribution helps the project.

Thank you for helping build Bridge Linux.
